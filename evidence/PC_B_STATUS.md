# PC B — état observé

Mis à jour le 28 octobre 2026 avec Sanad. Les configurations décrites ne prouvent pas les communications entre VM ou entre PC.

- **SW-B** : Alpine est installé sur disque, avec 512 Mio de RAM. Trois interfaces sont configurées : VMnet12/eth1 pour le trunk VLAN 20 et 30 ; VMnet10/eth2 pour l'accès Ubuntu VLAN 20 ; VMnet11/eth0 pour l'accès TrueNAS VLAN 30. Après redémarrage, `bridge vlan show` a affiché les VLAN attendus et `ip -br addr` les interfaces actives sans adresse IP, hors loopback. NAT temporaire retiré. SW-B est actuellement arrêté pour libérer de la RAM.
- **Différence documentaire** : l'accès Ubuntu utilise VMnet10 sur B, alors que les guides mentionnent VMnet14. Les numéros VMnet sont locaux à l'hôte ; UBU-LAB devra utiliser le même VMnet que le port Ubuntu de SW-B. Aucune modification du réseau n'est faite sur cette base.
- **Ubuntu** : Ubuntu Desktop 26.04.1 LTS a été installé sur UBU-LAB (4 Gio, disque 40 Gio), puis a démarré depuis son disque. Après mise à jour et redémarrage, noyau `7.0.0-42-generic` observé ; une mise à jour Orca reste proposée. Dans l'invité, `free -h` indiquait 3,3 Gio visibles et 2,2 Gio disponibles, et `/` environ 27 Gio libres. La carte NAT temporaire `enp0s17` avait 192.168.228.134/24 ; un ping vers ubuntu.com a répondu 3 fois sur 3. Ubuntu est ensuite éteint. La connexion finale VMnet10 et son adresse restent à configurer.
- **TrueNAS** : NAS-LAB est éteinte, avec 6 Gio et 2 vCPU. L'installateur TrueNAS 25.10.7 a confirmé la réussite de l'installation sur `sda`, identifié par position SCSI comme `NAS-boot.vmdk` (20 Gio). `sdb` et `sdc` correspondent aux deux disques de données `NAS-data-1.vmdk` et `NAS-data-2.vmdk`, non sélectionnés pour l'installation. La VM utilise le firmware BIOS ; la carte NAT est temporaire. L'ISO reste associée au CD/DVD et sa déconnexion avant le prochain démarrage reste à vérifier. Un redémarrage a été demandé après installation, mais la capture finale montre la VM éteinte : le démarrage depuis le disque installé n'est pas confirmé. Aucun pool de données n'est encore configuré. 6 Gio est inférieur au minimum documenté de 8 Gio ; aucune charge simultanée n'a été vérifiée.
- **Ressources** : avant le démarrage de TrueNAS, environ 7,58 Gio de RAM disponibles ont été observés sur Windows après fermeture d'applications ; le panneau VMware affichait précédemment environ 99,4 Go libres sur le disque hôte. Ce sont des mesures ponctuelles à reprendre au prochain démarrage.
- **À faire** : vérifier la déconnexion de l'ISO, démarrer TrueNAS depuis son disque et vérifier son état ; retirer ou reconfigurer les NAT temporaires pour les réseaux finaux ; configurer le stockage et vérifier les connexions locales ; coordonner le test du trunk 20/30 avec PC A. Aucun transport VLAN physique, routage inter-VLAN, VPN, service applicatif, restauration NAS ou test de charge simultanée n'est confirmé.
